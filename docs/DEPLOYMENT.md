# Deploying HikeCast

Target topology, chosen to cost **nothing** (DECISIONS 019):

**Neon** (Postgres + PostGIS, free) → **Render** (FastAPI backend from
`backend/Dockerfile`, free) → **Vercel** (React frontend, free — and it proxies
`/api/*` to Render).

Everything below has been verified locally except the provider steps, which
need your accounts. Expect ~30 minutes end to end.

---

## Two things to understand before you start

### 1. The browser only ever talks to Vercel

Vercel rewrites `/api/*` through to Render (`frontend/vercel.json`); the backend
is never called cross-origin from the browser.

This is what makes login work — see DECISIONS 017. Auth uses httpOnly cookies
with `SameSite=Lax`, and a `Lax` cookie is **not sent on cross-site requests**.
If the frontend called the Render domain directly, login would return 200 and
every request after it would 401.

**Consequence:** do **not** set `VITE_API_URL` in the Vercel dashboard.
`frontend/.env.production` pins it to the relative `/api/v1` on purpose.
Overriding it recreates exactly the bug this design avoids.

### 2. The free backend sleeps

Render spins a free service down after **15 minutes without inbound traffic**,
and the next request takes **about a minute** to wake it. That is the price of
$0/month, and for a demo it's fine — but it is not a surprise you want during a
presentation.

**Before you present: open the app 2–3 minutes early.** It then stays awake for
the whole demo. Keep a local `npm run dev` + `uvicorn` as a fallback.

## 1 — Database (Neon)

1. Create a project, region **EU (Frankfurt)** — closest to Render's Frankfurt
   region and to the users. No credit card required.
2. Enable the extensions in Neon's SQL editor:

   ```sql
   CREATE EXTENSION IF NOT EXISTS postgis;
   CREATE EXTENSION IF NOT EXISTS pgcrypto;
   ```

   Both are required — PostGIS for saved-location and trail geometry, pgcrypto
   for UUID generation. Migrations fail without them.
3. Copy the connection string. Paste it **verbatim** wherever it's needed. The
   libpq form (`postgresql://…?sslmode=require`) is normalized in
   `app/core/config.py` — driver swapped to asyncpg, `sslmode` translated to a
   TLS argument (DECISIONS 018, unit-tested in `tests/test_config.py`). No
   hand-editing.

Free plan: 0.5 GB storage, 100 CU-hours/month, sleeps after 5 minutes idle but
wakes in about a second. Not a demo risk.

## 2 — Backend (Render)

Dashboard → **New** → **Blueprint** → select this repo. Render reads
`render.yaml`, which already specifies the Docker build, the Frankfurt region,
the free plan, and `/health` as the health check.

It will prompt for the two values marked `sync: false`:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | the Neon string from step 1, verbatim |
| `CORS_ORIGINS` | your Vercel URL, e.g. `https://hikecast.vercel.app` — you won't have it until step 3, so put a placeholder and correct it after |

`JWT_SECRET` is generated by Render automatically (long and random — do not
paste the dev secret). `COOKIE_SECURE=true` and `PORT` are handled for you.

The container runs `alembic upgrade head` on start, so the schema is created on
first boot. Watch the deploy logs for `Application startup complete`.

Note the service URL — `https://<name>.onrender.com`. You need it for step 3.

### Seed the trails — from your laptop, not the server

Free Render services have **no shell access**, so seeding has to happen from
outside. This works because the seeder only needs the database:

```bash
cd backend
# PowerShell
$env:DATABASE_URL="<the Neon connection string>"; python -m app.seeds.trails
# bash
DATABASE_URL="<the Neon connection string>" python -m app.seeds.trails
```

It is idempotent (insert-only by default), so re-running is harmless. Use
`--update` only when correcting existing rows.

Skip `app.seeds.demo` unless you want the public demo account in production —
its password is published in the README.

**Remember to change `DATABASE_URL` back** (or open a fresh terminal) before
you next run the app locally, or you'll be developing against production.

## 3 — Frontend (Vercel)

Import the repo, root directory `frontend/`. `vercel.json` supplies the build
command, output directory, and the rewrites.

**Before the first deploy**, edit `frontend/vercel.json` and replace
`REPLACE-ME.onrender.com` with the real Render domain from step 2. It is a
placeholder — until you change it, the app proxies to nothing.

Set **no** environment variables. `.env.production` covers what's needed.

Once deployed, go back to Render and correct `CORS_ORIGINS` to the real Vercel
URL.

## 4 — Post-deploy verification

In this order — each catches a distinct failure:

```bash
# 1. Backend is alive. Hits RENDER directly: /health sits outside /api, so the
#    Vercel rewrite doesn't cover it — through the proxy it would fall through
#    to the SPA and return index.html. Allow ~1 min if the service is asleep.
curl -s https://<name>.onrender.com/health

# 2. Proxy is wired, plus database + PostGIS + seeds — should list 25 trails.
#    Getting HTML back means the rewrite destination is still REPLACE-ME.
curl -s https://<app>.vercel.app/api/v1/trails | head -c 200

# 3. Open-Meteo reachable from Render, scoring works, RO localization works.
curl -s -H "Accept-Language: ro" \
  "https://<app>.vercel.app/api/v1/forecast?lat=45.44&lng=25.45&days=1" | head -c 300
```

Then in a real browser — the only way to test the cookie path:

1. Register a new account.
2. Confirm both cookies land on the **Vercel** domain with `Secure` and
   `SameSite=Lax` (DevTools → Application → Cookies).
3. Reload the page — you must still be signed in. *If this fails, the cookie is
   going cross-site: check that `VITE_API_URL` isn't overridden.*
4. Save a location, open the profile dialog, request "Best trails".
5. Delete the `hikecast_access` cookie and act again — the silent refresh should
   restore access without bouncing you to login.

## Open-Meteo blocks Render's IP — read this before demoing

`api.open-meteo.com` rate-limits by IP and refuses Render's shared outbound
address (DECISIONS 020). Geocoding and the ERA5 archive use different hosts and
still work; the *forecast* and *elevation* endpoints are the affected ones.

Two mitigations are in the code: the backend serves an expired cache entry
flagged `stale` instead of 502-ing, and the UI says so. But a location with
**no** cache entry at all still fails — we don't invent weather.

So before any demo, warm the cache from a machine Open-Meteo will talk to:

```bash
cd backend
# PowerShell
$env:DATABASE_URL="<Neon string>"; $env:FORECAST_CACHE_TTL_MINUTES="1440"
python -m app.seeds.warm_cache --days 7 --ipv4 45.36,25.46
```

That covers every trailhead and summit (so trails and recommendations work),
plus any extra `lat,lng` you pass. **Include `45.36,25.46`** — the map's default
view, the first thing that loads.

`--ipv4` is needed on networks that resolve Neon's IPv6 records but can't route
them; without it asyncpg spends its whole connect timeout on unreachable
addresses. Harmless to pass always.

Entries live for `FORECAST_CACHE_TTL_MINUTES`, so **re-run it the morning of
the presentation.** After expiry the stale fallback keeps serving the same data
with a visible "showing saved data" banner.

## Costs

| Service | Plan | Cost | Limit that actually binds |
| --- | --- | --- | --- |
| Neon | Free | $0 | 0.5 GB storage, 100 CU-hours/mo |
| Render | Free | $0 | 750 instance-hours/mo; sleeps after 15 min idle |
| Vercel | Hobby | $0 | 100 deploys/day, 100 GB transfer |

**Total: $0/month.** Nothing here asks for a card.

If cold starts ever become unacceptable, the smallest fix is a paid backend
instance (Render Starter or Railway Hobby, both ~$5/mo) — the container is
host-neutral, so it's a config change, not a rewrite.

**Do not "switch to Netlify because it's free."** Its free tier is now
credit-based: 300 credits/month with **15 credits per production deploy**, so
roughly 20 production deploys a month, shared with bandwidth — and the project
pauses when they run out. Vercel Hobby allows 100 deploys per *day*. Netlify
also caps proxied requests at roughly 30 s versus Vercel's documented 120 s.

## Known gaps, accepted for this deploy

- **Cold starts** on the free backend — see above; warm it before demoing.
- **No refresh-token rotation** — DECISIONS 007 accepted this for v1.
- **`/docs` and `/redoc` are public.** Fine for a portfolio project; every
  mutating route is auth-gated.
- **AI packing advice returns 503** by design while `ANTHROPIC_API_KEY` is
  unset (DECISIONS 012). If it's ever switched on, note that a slow local
  Ollama call (20–60 s) would sit uncomfortably close to proxy timeouts.
